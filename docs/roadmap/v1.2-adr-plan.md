# v1.2 ADR Plan

| ADR ID | Topic | Required Before | Decision Scope | Required Evidence | Risk |
| --- | --- | --- | --- | --- | --- |
| ADR-v1.2-001 | Position persistence | Any Position IndexedDB store or repository mutation | Store schema, owner indexes, migration order, backup coverage, restore behavior, audit evidence, rollback limits | Backup/restore E2E, migration validation, owner isolation tests | High |
| ADR-v1.2-002 | Backup schema versioning | Any backup payload schema change | Version identifiers, compatibility matrix, dry-run behavior, rejection of future versions, encrypted backup compatibility | Backup security validation, restore dry-run evidence | High |
| ADR-v1.2-003 | CSV import safety | Any CSV import UI or parser | Entity mapping, validation errors, duplicate handling, partial import behavior, audit records | Fixture imports, malformed CSV tests, security review | Medium |
| ADR-v1.2-004 | External data boundary | Any exchange rate or remote notification research promotion | Static-first compatibility, no secret handling, no runtime network dependency, offline fallback | Architecture review, PWA/offline validation | High |

## Rule

An ADR can reject implementation. Rejection is a valid outcome when the static-first, local-first, offline-first boundary cannot be preserved.
