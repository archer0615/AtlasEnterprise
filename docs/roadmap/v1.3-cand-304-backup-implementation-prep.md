## First Runtime Batch

Backup hardening should ship with Position changes only if it preserves these behaviors:

1. Unsupported schemas reject before mutation.
2. Dry-run reports migration and store plan before staged restore.
3. Restore conflict policy remains explicit.
4. Existing records remain readable after failed restore validation.
5. Encrypted backup checksum and payload validation stay mandatory.

## Non-Goals

- Remote backup storage.
- Cloud sync.
- Automatic rollback deletion.
- Credential storage.
- Server-side restore.

## Required Validation

- `npm run test:backup-schema-v2-fixtures`
- `npm run test:backup-schema-compatibility`
- `npm run test:backup-restore-ux`
- `npm run test:backup-restore-e2e`
- `npm run validate:backup-security`
- `npm run validate:feature`

## Exit Criteria

Any backup runtime change must include an implementation report proving unsupported payload rejection before mutation and no destructive rollback behavior.
