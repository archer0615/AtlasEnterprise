# v1.3 Position CSV Mapping Specification

## Scope

This specification defines the CSV mapping required before Position CSV commit can be implemented.

## Required Columns

| CSV Column | Position Field | Required | Rule |
| --- | --- | --- | --- |
| `positionId` | `positionId` | Yes | Stable unique key for the local Position record. |
| `ownerId` | `ownerId` | Yes | Must match the active owner context before commit. |
| `householdId` | `householdId` | Yes | Required for household-scoped isolation. |
| `portfolioId` | `portfolioId` | Yes | Required for portfolio query and backup restore scope. |
| `assetId` | `assetId` | Yes | Required link to the held asset. |
| `quantity` | `quantity` | Yes | Must be a finite number greater than 0. |
| `unitCost` | `unitCost` | No | Must be a finite number greater than or equal to 0 when present. |
| `marketValue` | `marketValue` | No | Must be a finite number greater than or equal to 0 when present. |
| `currency` | `currency` | Yes | Must use an existing Atlas currency code. |
| `status` | `status` | Yes | Must be `active`, `closed`, or another accepted Position domain status. |
| `updatedAt` | `updatedAt` | Yes | Must be a valid ISO timestamp. |

## Dry-Run Rules

- Reject rows missing `positionId`, `ownerId`, `householdId`, `portfolioId`, `assetId`, `quantity`, `currency`, `status`, or `updatedAt`.
- Reject cross-owner rows before mutation.
- Report unsupported columns.
- Report duplicate `positionId` values in the same file.
- Report existing-record conflicts before commit.
- Keep row numbers and original values in validation output.

## Commit Rules

- Commit must only run after a successful dry-run.
- Commit must be scoped to Position rows only.
- Commit must not create Assets, Portfolios, Households, or Owners.
- Commit must preserve backup schema v2 compatibility.
- Partial commit is not allowed until explicitly specified.
