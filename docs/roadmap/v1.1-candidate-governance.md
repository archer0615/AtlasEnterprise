# v1.1 Candidate Governance

## Gate Rules

| Gate | Requirement | Failure Result |
| --- | --- | --- |
| Catalog Naming | Uses existing Atlas naming only. | Rejected |
| Business Concept | Does not create a new business concept. | Rejected |
| Canonical Source | Maps to authoritative knowledge. | Needs Specification |
| Static-first | Works on GitHub Pages. | Rejected or Needs Architecture Decision |
| Local-first | No backend, remote database, cloud runtime, or telemetry. | Rejected |
| Offline-first | Works without network after shell is available. | Conditional |
| Schema Safety | No migration without backup, restore, owner index, and tests. | Blocked |
| Formula Safety | No new formula without canonical precision and zero handling. | Needs Specification |
| State Machine Safety | No new state without lifecycle specification. | Needs Specification |
| Security | No secret, remote service, raw error, or sensitive cache. | Rejected |
| Accessibility | No release blocking accessibility issue. | Conditional |
| Validation | Has quick, feature, full, and release profile path. | Conditional |
