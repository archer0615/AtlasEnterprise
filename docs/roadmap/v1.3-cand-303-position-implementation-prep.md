# v1.3 CAND-303 Position Implementation Prep

## Scope

CAND-303 prepares the first v1.3 Position runtime expansion after the release evidence blocker is closed or explicitly deferred.

## Current Evidence

| Area | Evidence | Status |
| --- | --- | --- |
| IndexedDB store | `frontend/src/indexeddb-runtime.js` includes `positions` store, indexes, backup allowlist, export, restore, and repository methods. | Present |
| Domain contract | `frontend/src/domain/position/position-repository-contract.js` normalizes owner-scoped Position records. | Present |
| UI entry | `frontend/src/features/portfolio/portfolio-view.js` and `test:position-ui-entry`. | Read-only present |
| Migration gate | `test:position-indexeddb-migration`. | Passing |
| Repository gate | `test:position-repository-contract`. | Passing |
| Persistence gate | `test:position-persistence-gates`. | Passing |

## First Runtime Batch

The first eligible implementation batch should stay narrow:

1. Keep Position create/update/list behavior local-only.
2. Preserve owner, household, portfolio, and asset boundaries.
3. Keep backup schema v2 compatibility enabled.
4. Keep UI mutation behind explicit validation and no automated financial execution.
5. Keep CSV Position commit disabled until CAND-305 Position mapping is complete.

## Non-Goals

- Broker integration.
- Market price API.
- Portfolio rebalancing automation.
- Cloud sync.
- Backend API dependency.

## Required Validation

- `npm run test:position-persistence-gates`
- `npm run test:position-repository-contract`
- `npm run test:position-indexeddb-migration`
- `npm run test:position-ui-entry`
- `npm run test:backup-schema-compatibility`
- `npm run validate:feature`

## Exit Criteria

Runtime changes may start only after CAND-301 is closed or explicitly deferred and the first batch acceptance criteria are copied into an implementation report.
