# v1.2 Roadmap

| Phase | Purpose | Entry Criteria | Candidate IDs | Dependencies | Validation | Exit Criteria | Risks | Size |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Phase 0 - Planning Baseline | Close v1.1 and establish v1.2 governance. | `v1.1.0` tag, clean tree | CAND-101..107 | None | `validate:planning-baseline`, `validate:next-release-planning` | v1.2 inventory accepted | Documentation drift | Small |
| Phase 1 - Specification Completion | Define canonical behavior before implementation. | Canonical source identified | CAND-101, CAND-103 | Knowledge docs | `validate:status-traceability`, `validate:roadmap-architecture` | Specs complete and linked | New concept drift | Medium |
| Phase 2 - Architecture Decisions | Decide persistence, migration, backup, rollback, and offline constraints. | Spec candidates scoped | CAND-102, CAND-105 | ADR draft | `validate:roadmap-architecture`, `validate:backup-security` | ADR accepted or rejected | Data loss, rollback failure | Medium |
| Phase 3 - Evidence-Based Performance | Add benchmark automation only when measured evidence exists. | Measured bottleneck | CAND-104 | Baseline metrics | `benchmark:quality-baseline`, `validate:full` | Benchmark gate justified | False-positive regression gate | Small |
| Phase 4 - Research Boundaries | Reassess excluded cloud/external capabilities without changing runtime. | Static-first boundary retained | CAND-106, CAND-107 | Research notes | `validate:roadmap-architecture` | Remain rejected or receive future ADR | Scope creep | Small |
| Phase 5 - Implementation Queue Selection | Promote only candidates with passed gates. | Completed specs/ADRs | TBD | Prior phases | `validate:feature`, `validate:full` | First v1.2 implementation batch selected | Premature runtime work | Small |

## Result

v1.2 starts as planning-only. The first implementation batch is intentionally not selected until specification and ADR gates pass.
