# v1.3 CAND-304 Backup Rollback Test Plan

## Scope

CAND-304 covers backup restore rollback hardening for local-only IndexedDB restore flows.

## Test Cases

| Case ID | Scenario | Expected Result | Required Gate |
| --- | --- | --- | --- |
| C304-001 | Unsupported backup schema version is imported. | Restore rejects before mutation and reports unsupported schema. | `test:backup-schema-compatibility` |
| C304-002 | Backup payload has valid envelope but missing required store metadata. | Dry-run fails before staged restore. | `test:backup-schema-v2-fixtures` |
| C304-003 | Restore conflicts with existing local record by owner scope. | Conflict is reported and no cross-owner mutation occurs. | `test:backup-restore-ux` |
| C304-004 | Rollback occurs after restore validation failure. | Existing IndexedDB records remain readable. | `test:backup-restore-e2e` |
| C304-005 | Encrypted backup envelope has invalid payload hash. | Restore rejects before decrypt or mutation side effects. | `validate:backup-security` |
| C304-006 | Future payload includes unknown capability. | Capability is reported as unsupported and restore remains blocked. | `test:backup-schema-compatibility` |

## Runtime Boundary

- No cloud backup service.
- No remote sync.
- No destructive rollback.
- No hidden migration when dry-run fails.

## Exit Criteria

- All required gates pass.
- Conflict policy is documented before runtime changes.
- Unsupported payloads are rejected before mutation.
